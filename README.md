# HoldTracker

카메라로 운동 **횟수·홀드 시간·Cindy 챌린지**, 직접 측정한 **유연성 벤치마크와 스트레칭 훈련**을 기록하는 웹앱입니다.
정면은 화면을 보며 횟수·시간을 추정하고, 측면은 자세 기준 분석을 함께 제공합니다. 정면 플란체·레버는 선택한 동작의 3D 자세를 추정하여 자동 시간·영상 기록을 시도합니다. 정면 자세 값은 추정이며 측면 점수와 별도로 표시합니다.

모든 처리는 브라우저 안에서(온디바이스) 이뤄집니다. **영상은 어디에도 전송되지 않고**, 시간·자세 기록은 localStorage, 녹화 영상은 같은 브라우저 IndexedDB에 저장됩니다.

## 쓰는 법

1. 폰이나 PC 브라우저로 접속
2. 운동을 고르고 **앞에서 · 화면 보며** 또는 **옆에서 · 자세 분석** 선택
3. 동작별 안내에 맞게 거치하고 `카메라 켜기` → `5초 뒤 시작`
4. 운동 중 횟수·시간을 확인하고 `운동 마치기` → 결과 확인. 자동 감지 범위와 녹화 방식은 아래 정면 촬영·자동 녹화 안내 참고

폰에서는 **홈 화면에 추가**하면 앱처럼 전체화면으로 실행됩니다.

## 측면 자세 판정 방식

MediaPipe BlazePose로 33개 관절 랜드마크의 3D 좌표를 추출한 뒤, 규칙 기반으로 판정합니다.

| 신호 | 쓰임 |
|---|---|
| 손목 vs 어깨 높이 | 매달림(레버류) / 바닥 지지(플란체·L-sit·핸드스탠드) 구분 |
| 배 방향 법선 (몸통축 × 어깨선) | 프론트 레버 vs 백 레버 구분 |
| 발 높이 vs 손 높이 | 플란체 vs 푸시업 플랭크 구분 |
| 고관절/무릎 각도 + 발목 벌림 | 턱 / 어드밴스드 턱 / 하프 / 스트래들 / 풀 |

동작별 가중 점수(0~100):

- **플란체** — 수평 34% · 팔 폄 24% · 어깨 전방 이동 20% · 몸 일직선 22%
- **프론트/백 레버** — 수평 38% · 팔 폄 24% · 허리 처짐 14% · 몸 일직선 12% · 어깨각 16%
- **L-sit** — 몸통 수직 30% · 다리 수평 30% · 무릎 폄 24% · 팔 폄 16%
- **핸드스탠드** — 전신 수직 45% · 팔 폄 25% · 몸 일직선 30%

가중평균만 쓰면 한 항목이 크게 무너져도 통과하므로, **가장 나쁜 항목이 총점을 제한**합니다 (`총점 = min(가중평균, 45 + 55 × 최저항목)`).

타이머는 `IDLE → ARMING(안정화) → HOLDING → BREAKING(유예)` 상태머신입니다. 운동 감지로 시간 기록을 시작하며 자세 점수는 별도로 평가합니다. 운동이 다시 감지되지 않는 유예 구간은 시간에 더하지 않습니다.
**총 시간**과 **클린 시간**(기준 이상을 유지한 시간)을 따로 기록합니다.

## 알려진 한계

- 수평/수직을 화면 축 기준으로 재기 때문에 **카메라가 기울면 부정확** → 설정의 `수평 보정`으로 보정
- **자세 점수 분석은 측면 기준**. 정면에서는 별도 횟수·시간 추정 또는 3D 자세 추정을 사용하며 정확한 깊이·기울기·접촉을 판정하지 않음
- BlazePose는 서 있는 자세 위주로 학습되어 **거꾸로/수평 자세에서 랜드마크가 흔들릴 수 있음**
- 각도 임계값이 고정값이라 체형에 따라 편차가 있을 수 있음 (설정에서 기준 점수 조절 가능)

## 구성

단일 정적 사이트입니다. 빌드 과정이 없습니다.

```
index.html              메인 UI + 판정 로직 + 기록
front-tracking.js       정면 측정 엔진
workout-video.js        운동 구간 로컬 영상 저장
flexibility.js          유연성 기록 + 훈련 타이머
manifest.webmanifest    PWA 매니페스트
sw.js                   서비스 워커 (앱 셸 network-first, 모델 CDN cache-first)
icon-*.png              아이콘
```

로컬 실행:

```bash
python3 -m http.server 8777
# http://127.0.0.1:8777 접속
```

카메라 API는 보안 컨텍스트가 필요해서 `file://`로는 동작하지 않습니다. `localhost` 또는 HTTPS로 여세요.

## 통합 훈련 UI (v2)

홀드 측정과 스쿼트·푸시업·풀업 반복 추정을 같은 카메라와 포즈 모델로 처리합니다. 반복 판정은 개인 훈련용 실험 기능이며 공식 CrossFit 심판 판정이 아닙니다. 바닥 접촉, 실제 바 위치와 턱 통과는 직접 검출하지 않습니다. 버피와 싯업은 검증 전이므로 통합 버전에서 제외했습니다.

### 좁은 공간에서 촬영

- 휴대폰을 가로로 거치하고, 옆에서 머리·손·발이 들어오는지 확인하세요.
- 카메라가 실제로 노출하는 줌 범위만 사용합니다. 지원되는 경우 최저 줌으로 시작합니다.
- 전면 0.5배나 후면 초광각 렌즈 접근은 기기·브라우저 지원에 따라 다릅니다. CSS로 영상을 축소해도 촬영되지 않은 발은 복원되지 않습니다.
- 줌이 없으면 카메라 목록에서 다른 렌즈를 선택하거나 기본 카메라 앱으로 광각 촬영한 영상을 불러오세요.
- 잘림·추적 손실이 감지되면 측정을 진행하지 않습니다. 화면 안에 있어도 가림과 포즈 추정 오류로 인식하지 못할 수 있습니다.

### 검증 범위

합성 포즈·상태머신 테스트는 로직 검증이며, 실제 운동 영상의 정확도 검증과 다릅니다. 사용자 기기의 전면/후면 광각 지원과 실제 촬영 성능은 해당 기기에서 추가 확인이 필요합니다.


## 처음 사용하는 사람을 위한 흐름 (v3)

`운동 종류 선택 → 운동 선택 → 카메라 준비 → 시작 카운트다운 → 운동 → 결과`

첫 화면에는 횟수 세기, 버티는 시간, 시간제 챌린지만 보여줍니다. 카메라 렌즈·줌·파일 분석 같은 세부 옵션은 준비 단계에서만 열어볼 수 있습니다. 운동 중에는 현재 동작과 핵심 숫자, 마치기 버튼에 집중합니다.

Cindy는 20분 동안 풀업 5회 → 푸시업 10회 → 스쿼트 15회를 반복합니다. 점수는 완료 라운드와 다음 라운드에서 완료한 횟수입니다. 운동 사이 이동과 카메라 재배치 시간도 챌린지 시간에 포함됩니다. [CrossFit의 Cindy 설명](https://www.crossfit.com/cindy)

카메라가 판단한 반복 횟수는 훈련 보조용 추정값입니다. 종목 변경, 가림, 촬영각도에 따라 오차가 날 수 있으며 공식 경기 판정으로 사용할 수 없습니다. 링 로우·무릎 푸시업 등 대체 동작은 현재 인식 대상에 포함하지 않습니다.


## 정면 촬영 (v4)

준비 화면에서 **앞에서 · 화면 보며**(기본) 또는 **옆에서 · 자세 분석**을 선택합니다. 정면은 전면 렌즈를 요청하고 미러링 및 운동 중 미리보기를 기본으로 사용합니다. 브라우저/기기에 따라 요청한 렌즈가 제공되지 않을 수 있어 고급 설정에서 렌즈를 바꿀 수 있습니다.

- **푸시업·에어 스쿼트·풀업**: 정면 관절 이동과 시작 자세 보정을 이용해 반복 횟수를 추정합니다. 동작 중 추적이 끊기면 현재 반복을 버리고 시작 자세를 다시 확인합니다. 푸시업·풀업은 뒤에 가려지는 발 대신 해당 동작에 필요한 상체 관절을 확인하고, 스쿼트는 발목까지 요구합니다.
- **L-sit·핸드스탠드**: 정면의 대략적인 자세 조건으로 유지 시간을 추정합니다. 지지점·균형·정확한 폼을 확인하지 않습니다. 핸드스탠드 중 화면을 보려고 목을 꺾지 마세요.
- **플란체·프론트 레버·백 레버**: 선택한 동작의 3D 관절 위치로 수평 자세를 추정해 자동 시간을 기록합니다. 앞/뒤 방향과 실제 지지점을 자동 구별하지 않습니다. 3D 추정이 불안정하거나 관절이 잘리면 측정하지 않으며 대각 또는 측면을 권장합니다.
- **Cindy**: 정면 추정 횟수로 단계가 전환됩니다. 공식 경기의 유효 반복 판정이 아닙니다.

정면 기록에는 자세 점수·합격률·클린 시간을 붙이지 않습니다. 정면 홀드는 별도 `frontHolds` 컬렉션, 반복/챌린지는 `captureView`와 `judgement` 태그로 저장합니다. 기존 측면 기록·개인 기록은 유지됩니다. JSON 및 CSV로 정면 기록도 내보낼 수 있습니다.

`front-tracking.js`는 DOM과 저장소에 의존하지 않는 정면 전용 엔진입니다. 합성 랜드마크·화면 흐름 검증은 통과했으나 실제 사람 영상과 여러 기기의 정확도는 아직 검증되지 않았습니다.


## 자동 녹화와 시도 기록 (v5)

- 관절 추적, 운동 감지, 자세 점수는 별도입니다. 측면 홀드에서는 선택한 운동 조건을 안정적으로 감지하면 자세 점수와 무관하게 시간을 기록합니다. 0.5초 이상 시도를 남기고, 최소 클린 시간·점수 기준을 충족한 시도만 자세 기준 PB에 포함합니다. 정면 레버·플란체는 3D 추정 게이트로 감지하며 수치에는 추정 표시를 붙입니다.
- 준비 단계에서 자동 영상 저장을 끌 수 있습니다. 감지 안정화 후 MediaRecorder가 카메라 영상만 기록합니다. 소리는 녹음하지 않고 어떤 서버에도 업로드하지 않습니다. 홀드는 시도마다, 반복/챌린지는 첫 운동 움직임 감지 후 세션 단위로 녹화합니다.
- 영상은 브라우저 IndexedDB에 저장되고 결과와 기록 목록의 **영상·자세**에서 재생·다운로드합니다. 시도당 최대 2분·약 30MB입니다. 제한에 도달하면 일부 구간만 저장되며 UI에서 알려줍니다. 영상 길이는 감지 지연·종료 유예로 측정 시간과 다를 수 있습니다.
- 저장소가 차거나 브라우저가 지원하지 않으면 시간 기록은 유지하고 녹화 실패 안내를 제공합니다. 임시 영상은 페이지를 닫기 전에 다운로드해야 합니다. 브라우저 데이터 삭제·기기 변경 시 영상은 사라집니다. JSON에는 영상 바이트가 포함되지 않으므로 영상 다운로드는 별도입니다.
- 관절 좌표·자동 자세 판정은 실제 운동 영상 검증이 아직 필요합니다. 이번 합성 테스트는 상태 전이와 영상 저장/재생 기능 검증이며 실제 자세 정확도를 입증하지 않습니다.


## 유연성 벤치마크와 훈련 (v6)

- 첫 범위: pancake, middle split, front split 좌/우, ankle knee-to-wall 좌/우. 수치를 직접 측정해 cm로 기록합니다. 카메라에서 절대 거리(cm)를 자동 추정하지 않습니다.
- Pancake는 가슴 아래쪽의 바닥 간격, 발뒤꿈치 사이 폭, 좌면 높이를 기록합니다. Split은 골반 아래 지지 높이/바닥 간격을 기록하고 방향·발 방향·보조 방식을 구분합니다. 이 방식은 **앱의 개인 추적 프로토콜**이지 임상 검증된 pancake/split 검사나 180° 인증이 아닙니다. 가슴이 닿아도 허리 굽힘으로 범위를 과장할 수 있고, 골반이 돌아간 split도 같은 자세로 볼 수 없습니다.
- 준비운동 후·깊은 스트레칭 전의 기록과 훈련 직후 기록을 나눕니다. 같은 다리·측정 조건·보조 방식·통증 없는 자기 확인 기록끼리만 비교합니다. 작은 차이를 확실한 향상이나 부상 위험 감소로 판정하지 않습니다.
- Knee-to-wall은 맨발, 뒤꿈치를 바닥에 둔 채 무릎을 벽에 대고 엄지발가락에서 벽까지의 거리를 측정합니다. 좌우를 분리하며 보편적인 합격 거리나 cm→각도 자동 변환을 붙이지 않습니다.
- 훈련은 5–10분 가벼운 준비운동 뒤, 편안한 범위의 정적 스트레칭 30초 × 2세트부터 시작하는 보수적 예시입니다. 천천히 움직이는 힙힌지/가동성 연습과 휴식을 함께 제공합니다. 특정 split 달성을 보장하는 검증된 치료 프로토콜은 아닙니다. 반동·과도한 가압·oversplit·고강도 PNF·가중 Jefferson curl은 기본 루틴에서 제외합니다. 날카로운 통증, 관절 통증, 저림이 있으면 중단하고 반복되면 전문가에게 확인하세요.
- 타이머 시작만으로 완료 기록을 만들지 않습니다. 실제 수행 구간·중단/부분 완료를 구분하며 자동 반복 체크인이나 훈련 알림은 생성하지 않습니다.
- 다음 우선순위: active straight-leg raise(능동 햄스트링 범위), shoulder overhead flexion(핸드스탠드/오버헤드), hip 90/90 rotation. 아직 측정 기능은 넣지 않았으며, 각각의 표준화와 능동/수동 구분이 먼저 필요합니다.

### 참고 근거

1. [Ingram et al., 2025: 정적 스트레칭 용량 메타분석](https://pubmed.ncbi.nlm.nih.gov/39614059/) — 189개 연구·6654명 성인에서 관절 가동범위 향상을 보고했습니다. 더 세게/더 오래가 항상 더 좋다는 근거는 아닙니다. 논문의 4분/세션·10분/주 분석값을 개인의 필수 최소량이나 절대 상한으로 적용하지 않습니다.
2. [Mayo Clinic: basic stretches](https://www.mayoclinic.org/healthy-lifestyle/fitness/in-depth/stretching/art-20546848) — 준비운동 5–10분, 부드럽고 느린 스트레칭을 안내합니다.
3. [Chisholm et al., 2012: ankle lunge test reliability/validity](https://pmc.ncbi.nlm.nih.gov/articles/PMC3484905/) — 표준화된 체중부하 발목 측정의 신뢰도와 측정 오차를 다룹니다. 이 연구의 수치를 앱의 자가 측정 정확도로 보장하지 않습니다.
4. [Stretch Therapy: pancake movement](https://stretchtherapy.net/pancake-moving-sequence/) — 골반의 전방 기울임과 고관절 힌지 지도 참고. 코칭 자료이며 임상 검증/무작위 시험과 구분합니다.


## 출처별 유연성 측정·프로토콜 (v7)

### 서로 다른 기록법을 섞지 않기

- **전문가 출처 기반 수동 측정**: Lattice의 pancake 다리 벌림 각도(각도기로 직접 측정), 자세를 유지한 손 도달 거리, front split 앞·뒤 뒤꿈치 사이 거리. 출처와 앱의 추가 표준화 규칙을 함께 표시합니다.
- **앱 자체 보조 기록**: 기존 가슴뼈/골반 아래 바닥 간격, 다리 벌림 폭·좌면 높이 등. 기존 데이터는 유지하되 전문가 인증·임상 검증된 측정법으로 재표시하지 않습니다.
- **연구 기반 검사**: ankle knee-to-wall. 연구에서 검증한 검사와 앱의 자가 측정 정확도는 구분합니다.
- 새 각도 기록은 °, 거리 기록은 cm입니다. 방법별 protocolId, 좌우, 지지 방식, 측정 시점 및 구도 조건이 같은 기록끼리만 비교합니다. 기존 바닥 간격과 새 뒤꿈치 거리/각도/도달 거리는 하나의 PB로 합치지 않습니다.
- Lattice는 손 도달 거리의 정확한 0점 기준을 지정하지 않습니다. 앱은 **사용자가 고정 기준선을 정하고 이름을 기록하는 규칙**을 추가했습니다. 이 기준선·조건 일치 규칙은 앱의 반복 측정 설계이지 Lattice 공식 규격이 아닙니다.
- Pancake 접촉 관찰(팔꿈치·팔뚝·머리·가슴·배)은 자기 보고입니다. 순위를 점수화하지 않으며 가슴만 닿았다고 정확한 pancake나 180° 달성을 인증하지 않습니다.
- Front split은 앱에서 비교를 위해 골반 정면 조건을 선택했습니다. Lattice는 클라이밍 목적에서는 일부 골반 회전이 허용될 수 있다고 설명하므로, 앱의 엄격한 조건과 원문의 목적별 허용 범위가 다르다는 점을 표시합니다.
- 기존 v1 기록과 새로운 방법별 v2 기록을 보존하고 JSON/CSV에 단위·protocolId·출처·관찰 항목을 포함합니다.

### 출처와 앱 변형을 함께 보여주는 훈련

기존 30초 × 2세트·20초 휴식은 **앱의 일반 저강도 템플릿**입니다. 새 Lattice 참고 루틴은 자세 인식/제어 → 준비 동작 → 가동범위 → 끝범위 근력의 구조를 참고하지만, 원문의 전체 세션을 복제하거나 공식 프로그램/개인 처방으로 제공하는 것은 아닙니다. 각 단계에 원문 권장량과 앱의 축소·저강도 변형을 구분해 보여줍니다. 무게 추가, 최대 견딜 강도, oversplit·반동을 자동 권장하지 않습니다.

수동 반복 단계는 사용자가 실제 수행 후 완료를 확인합니다. 유지 동작 타이머 시간과 수동 반복/휴식은 구분하며, 타이머 시작만으로 완료 기록을 만들지 않습니다. 원문에 제시된 pancake 약 12주·front split 8–12주 재측정은 안내 문구일 뿐, 자동 일정/체크인으로 만들지 않습니다.
